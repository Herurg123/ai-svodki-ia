# Пятый этап: публикация VK

## Запуск

Оркестратор full-worker.js вызывает vk-stage.mjs **строго после** scheduled-worker.js,
dzen-collections.js и dzen-article-video.js. Для запуска требуются успешные
статусы DONE, PUBLISHED, COMPLETE и COMPLETE/SKIPPED_EXISTING у одного
job **за текущую дату**, сохранённые ссылки на статью и видео Дзена, читаемый
MP4 соответствующей даты и локальный одноимённый PNG. Размер MP4 и его
SHA-256 сверяются с результатами предыдущих этапов, если они сохранены.

Видео и PNG используются из downloads, не загружаются с FTP и не генерируются
снова. full-worker.js владеет общим lock; отдельный Task Scheduler или новый
профиль Яндекс.Браузера для VK не создаются. Ошибка VK не откатывает Дзен,
но влияет на итоговую ошибку комбинированного запуска.

## Шаблон публикаций

Отдельный операторский файл vk-publication-template.txt живёт в корне
NotebookLMBot. Его нельзя путать с downloads/_ИИ-Сводка.txt:
последний является описанием предыдущих этапов и может перезаписываться.

Модуль vk-text.mjs извлекает текст после точных маркеров
«+++ Тема / Название:» и «+++ Описание:». Даты DD/MM/MMMM/YY/YYYY и
YYYY-MM-DD берутся из job.date. Вместо строки
«% URL сводки этого дня в Дзен %» используется
job.dzenArticleVideo.articleUrl; адрес исходной сводки берётся из
job.publicationUrl. В пост вставляются тема и всё описание без маркеров.
Контрольная сумма конечных текстов сохраняется в checkpoint, чтобы после
частичного запуска не продолжать работу с изменённым шаблоном.

## Общая конфигурация

В локальном config.json должна быть секция:

~~~json
"vkPublish": {
  "enabled": true,
  "automaticEnabled": false,
  "groupId": 240277058,
  "playlistId": 1,
  "playlistTitle": "Сводки по ИИ",
  "accessFile": "C:\\TRASH\\NotebookLMBot\\vk-access.json",
  "templateFile": "C:\\TRASH\\NotebookLMBot\\vk-publication-template.txt"
}
~~~

Оба параметра enabled и automaticEnabled по умолчанию false в шаблоне
конфигурации. Токен сообщества из временного .env нельзя вставлять открытым
текстом в config.json. В рабочей папке Windows запустить:

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\configure-vk-access.ps1
~~~

Скрипт переносит VK_GROUP_ID в config.json, защищает VK_GROUP_TOKEN с
Windows DPAPI CurrentUser в vk-access.json, создаёт резервную копию
config.json и не удаляет временный .env. automaticEnabled остаётся false.
.env, vk-access.json и действующую конфигурацию нельзя коммитить.

## Последовательность и сохранение состояний

Единая секция job.vkPublication в существующем state.json хранит
даты, ID, фазы и диагностические ошибки. Журналирование осуществляется
через существующий log-utils.js; history-utils.js оставляет незавершённую
VK-публикацию в активном состоянии.

1. video.save, передача существующего MP4, video.publish, проверка video.get.
2. Добавление того же видео в целевой плейлист через video.addToAlbum и
   подтверждение membership через video.getAlbumsByVideo.
3. Один wall.post с прикреплённым видео, ссылкой Дзена, стабильным guid.
4. История сообщества: исходный `downloads/ИИ-Сводка YYYY-MM-DD.png` передаётся
   на сервер VK **без преобразования, обрезки, масштабирования или надписей**.
   К нему прикрепляются прежние post sticker и ссылка на Дзен.
   Проверка через stories.getById.

Перед необратимыми запросами запись phase *_REQUESTED сохраняется
на диск. После неоднозначного ответа video.save, video.publish,
wall.post или stories.save запрещено вслепую повторять операцию.
Чтение wall.get с ключом сообщества возвращало API 27 и поэтому не
является допустимым доказательством отсутствия поста; stories.get
может не показывать историю, которая доступна через stories.getById.

VK Видео использует проверенный в опытах, но **недокументированный**
клиентский endpoint api.vkvideo.ru и временный токен, извлекаемый
только из существующего CDP-профиля Яндекс.Браузера. Других профилей,
браузерных VK UI-кликов или сохранения этого токена нет.

## Ограничение пользовательской подписи истории

В проверенной схеме VK Stories параметр link_text принимает фиксированные
значения, например read («Читать»). По решению оператора никакую подпись
не рисуем поверх исходного PNG; кнопку ссылки оставляем «Читать».
Автопубликация остаётся выключенной до завершения review и установки.

## Контроль и развёртывание

Video CI выполняет npm test и syntax checks без реальных обращений к VK.
Для просмотра состояния без мутаций:
~~~bat
node vk-stage.mjs --date=YYYY-MM-DD
~~~
Режим --apply изменяет реальные публикации и не предназначен для диагностики.
Не включать automaticEnabled до review, явного merge, установки и
отдельного решения владельца.

Успешные живые испытания 17.10.2026 подтверждали все отдельные операции;
результат точной сквозной интеграции требует независимой проверки.
