# Нативная загрузка видео в Дзен через локальный Яндекс.Браузер

Этот документ описывает **экспериментальный операторский** browser-upload путь
для уже готового NotebookLM MP4. Он использует тот же защищённый профиль
Яндекс.Браузера и Playwright/CDP, который уже применяется локальным video-worker.

Путь пока **не подключён** к `worker.js`, `run-worker.cmd`,
`run-worker-hidden.vbs` или Планировщику Windows. Обычный запуск NotebookLM worker
не публикует видео в Дзен. Финальная публикация выполняется только отдельной
явной операторской командой `run-dzen-publish.cmd`.

## Подтверждённый ручной сценарий 27.08.2026

На канале «Заметки из подпространства» проверено:

1. Дзен-студия открывается в защищённом профиле Яндекс.Браузера.
2. Кнопка создания публикации открывает меню с пунктом «Загрузить видео».
3. Локальный MP4 выбирается через стандартный file input.
4. После выбора MP4 создаётся URL с `videoEditorPublicationId`.
5. Форма «Публикация видео» содержит название, описание, обложку, теги и
   настройку «Кто может комментировать».
6. Локальный PNG принимается как пользовательская обложка без обязательного
   дополнительного кадрирования.
7. После обработки Дзен показывает «Загрузили и обработали видео» и активирует
   кнопку «Опубликовать».
8. Ручная публикация этим путём появилась именно в разделе **«Видео»**.

Это текущий эталонный UI-сценарий. RSS-путь для нативного Video ранее закрыт как
неуспешный, см. `DZEN_VIDEO_EXPERIMENTS.md`.

## Реализация

Подготовительный helper `dzen-publish.js`:

- запускается с `--dry-run`;
- берёт выпуск из `state.json` по дате;
- использует `job.downloadedFile` как локальный MP4;
- использует `job.previewFile` или соседний PNG; если PNG отсутствует, создаёт его
  через уже установленный `ffmpeg-static`;
- подключается к уже запущенному роботизированному Яндекс.Браузеру по CDP либо
  запускает тот же `browserExecutable` с тем же `browserProfile`;
- проверяет авторизацию и имя канала;
- выбирает «Загрузить видео» и передаёт локальный MP4 через Playwright;
- сохраняет `videoEditorPublicationId` и draft URL в `state.json`;
- заполняет название и описание;
- загружает PNG через «Добавить обложку»;
- добавляет ровно пять тегов и после каждого подтверждает отдельную tag-chip;
- при необходимости кликает точную popup-подсказку;
- отдельно проверяет, что пятый тег реально добавлен;
- пытается выставить «Кто может комментировать» = «Все пользователи»;
- если dropdown комментариев не удалось переключить, продолжает и пишет в общий
  `worker.log` строку с префиксом `!!! DZEN:`;
- ждёт состояния «Загрузили и обработали видео» и активной кнопки
  «Опубликовать»;
- сохраняет diagnostic screenshot и статус `READY_TO_PUBLISH`.

Финальный helper `dzen-publish-live.js` затем:

1. переиспользует подготовительный flow;
2. перед кликом открывает Studio → «Публикации» → «Видео» и считает уже
   существующие записи с тем же заголовком;
3. сохраняет этот baseline в `state.json` и переводит job в `PUBLISHING`;
4. нажимает **«Опубликовать»**;
5. сразу переводит состояние в `PUBLISH_CLICKED_UNVERIFIED`;
6. повторно проверяет вкладку **«Видео»**;
7. помечает job как `PUBLISHED` только если число одноимённых записей стало больше
   сохранённого baseline;
8. сохраняет screenshot результата и найденный URL, если его удалось извлечь из
   Studio.

Проверка по увеличению числа одноимённых строк нужна потому, что тестовый выпуск
27 августа уже имеет вручную опубликованное видео с тем же заголовком. Простая
проверка «такой заголовок есть» дала бы ложный успех.

## Защита от повторного клика

Если после нажатия кнопки новая строка не появилась в течение контрольного окна,
сохраняется `PUBLISH_CLICKED_UNVERIFIED`. Повторный запуск **не нажимает кнопку
ещё раз**, а только повторяет проверку вкладки «Видео».

Это не запрещает публикацию. Это защищает от создания дублей в ситуации, когда
клик мог сработать, а Studio обновилась с задержкой или проверка оборвалась.

Если состояние уже `PUBLISHED`, повторный операторский запуск является no-op.

## Метаданные

Название строится по дате выпуска:

```text
ИИ-Сводка на 27 августа 2026 | Подпишись, чтоб получать свежее!
```

Описание:

```text
Что происходит в мире Искусственного Интеллекта (ИИ, AI) и Нейросетей на текущий момент - коротенько о самом главном

Без рекламы и воды на 27.08.2026:
- Глобальные новости
- Новости ИИ России
- Выводы и тренды

Этот выпуск:
https://rybalka.one/posts/2026-08-27/
https://dzen.ru/suite/7971db4c-2a4e-449f-b8bf-c3907486d6f1
```

Дата и URL выпуска берутся из выбранного job, а не зашиваются на 27 августа.

Текущие пять тегов:

```text
ии
ai
полезныесоветы
будущее
лайфхак
```

## Ручной запуск

До отдельной promotion-задачи helper-файлы нужно положить рядом с существующим
`config.json` в локальный NotebookLMBot.

Реальная публикация:

```cmd
cd /d C:\TRASH\NotebookLMBot
run-dzen-publish.cmd --date=2026-08-27
```

Если `--date` не указан, используется текущая дата по `timeZone`.

Для диагностики без финального клика остаётся:

```cmd
run-dzen-dry-run.cmd --date=2026-08-27
```

Для ручного входа/проверки профиля используется `open-robot-browser.cmd`.

## Что смотреть после запуска

Основные признаки успеха:

- в `worker.log` есть подтверждение пяти tag-chip;
- для комментариев либо подтверждено «Все пользователи», либо есть заметная
  non-fatal строка `!!! DZEN:`;
- `state.json` содержит `videoEditorPublicationId`;
- после клика состояние проходит через `PUBLISHING` /
  `PUBLISH_CLICKED_UNVERIFIED`;
- итоговый статус `PUBLISHED` ставится только после подтверждения новой записи во
  вкладке «Видео»;
- в `screenshotsDir` есть контрольный `dzen-published-video-...png`.

Если helper завершился в `PUBLISH_CLICKED_UNVERIFIED`, вручную проверить Studio.
Повторный запуск не должен создавать ещё одну публикацию, он только повторит
проверку результата.

## Граница текущего эксперимента

Этот код уже способен выполнить реальный финальный клик, но всё ещё остаётся
**отдельной операторской экспериментальной командой**. В этом изменении он не
становится частью обычного `worker.js` и не запускается Планировщиком Windows.

После живого автоматического теста и обратной связи отдельно принимается решение
о promotion: подключать ли native Dzen upload как следующий идемпотентный этап
обычного локального NotebookLM worker flow.
