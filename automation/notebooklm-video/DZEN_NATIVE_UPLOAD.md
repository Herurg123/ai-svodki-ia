# Нативная загрузка видео в Дзен через локальный Яндекс.Браузер

Этот документ описывает **экспериментальный операторский** browser-upload путь
для уже готового NotebookLM MP4. Он использует тот же защищённый профиль
Яндекс.Браузера и проверенный browser/CDP bootstrap локального `worker.js`.

Путь **не подключён** к обычному `worker.js`, `run-worker.cmd`,
`run-worker-hidden.vbs` или Планировщику Windows. Реальная публикация выполняется
только отдельной явной операторской командой `run-dzen-publish.cmd`.

## Подтверждённый автоматический MVP

Контрольный live-run 28.08.2026 для выпуска 27.08.2026 успешно прошёл весь
операторский путь от запуска браузера до единственного клика `Опубликовать`.
Лог подтвердил:

1. роботизированный Яндекс.Браузер и CDP `127.0.0.1:9222` запускаются автоматически;
2. канал «Заметки из подпространства» подтверждается;
3. открывается форма «Публикация видео»;
4. MP4 загружается и появляется `videoEditorPublicationId`;
5. название и описание заполняются один раз;
6. PNG-обложка передаётся один раз;
7. подтверждаются все пять tag-chip;
8. правый нижний статус проходит `uploading -> processing -> ready`;
9. финальная кнопка публикации активна только после `Загрузили и обработали видео`
   + `Готово: можно публиковать и смотреть`;
10. `Кто может комментировать` выставляется в `Все пользователи`;
11. `Опубликовать` нажимается один раз;
12. браузер закрывается runner после завершения child.

Этот подтверждённый MVP является текущим каноническим live-flow.

## Browser bootstrap

`run-dzen-publish.cmd` запускает `dzen-browser-runner.js`, который использует
`browser-session.js` и тот же профиль/исполняемый файл/CDP lifecycle, что и
рабочий `worker.js`. Предварительно запускать браузер или CDP вручную не нужно.

Bootstrap не удаляет и не пересоздаёт browser profile, cookies, Google session,
Dzen session или session-файлы профиля.

Один явный live-запуск выполняет ровно один `dzen-publish-direct.js` child-проход.
Автоматический повтор полного live-flow после ошибки запрещён.

Проверка logout опирается на явный переход на URL авторизации
(`passport.yandex`, `oauth.yandex`, `sso.dzen.ru` и т.п.), а не на наличие
скрытых auth-input в DOM. На подтверждение нужного канала после открытия Studio
даётся до 30 секунд.

## Канонический live-flow

```text
новый upload
  -> videoEditorPublicationId только для лога/диагностики
  -> title/description один раз
  -> PNG cover один раз
  -> ровно 5 tag-chip
  -> metadata/cover/tags больше не трогать
  -> ждать финальный статус справа внизу
  -> comments = «Все пользователи»
  -> один клик «Опубликовать»/«Отправить»
  -> записать факт клика и draftId в лог
  -> завершить child
  -> runner закрывает браузер
```

### Что намеренно отсутствует

Текущий MVP **не** делает:

- reopen/resume по сохранённому `videoEditorPublicationId`;
- повторное открытие старых drafts;
- `previousDrafts`/`RETRY_NEW_DRAFT` в каноническом live-flow;
- повторное заполнение уже заполненных metadata;
- автоматический повтор child;
- baseline перед кликом;
- post-click verification через Studio → Видео;
- повторный клик публикации.

Если запуск падает **до** клика, следующая отдельная операторская команда начинает
новый upload. Старый remote draft автоматически не открывается и не удаляется.

Если лог уже содержит маркер успешного клика для конкретного запуска, повторять
тот же live-run вслепую нельзя: текущий MVP после клика не доказывает появление
публикации отдельной проверкой.

## Метаданные

Название строится по дате выпуска:

```text
ИИ-Сводка на 27 августа 2026 | Подпишись, чтоб получать свежее!
```

Описание текущего live-flow:

```text
Что происходит в мире Искусственного Интеллекта (ИИ, AI) и Нейросетей на текущий момент - коротенько о самом главном

Без рекламы и воды на 27.08.2026:
- Глобальные новости
- Новости ИИ России
- Выводы и тренды

Этот выпуск:

- https://rybalka.one/posts/2026-08-27/
- https://dzen.ru/suite/7971db4c-2a4e-449f-b8bf-c3907486d6f1
```

Обе ссылки после `Этот выпуск:` являются отдельными bullet-строками.

Описание после единственного заполнения проверяется без учёта пробельного
форматирования. Whitespace-only изменения, которые вносит Дзен, не запускают
повторный `fill()`. Непробельное изменение остаётся ошибкой.

## Теги

Текущие пять обязательных тегов:

```text
ии
ai
полезныесоветы
будущее
лайфхак
```

После каждого Enter DOM может перерисоваться. Поэтому locator поля тегов не
сохраняется как вечная ссылка: при необходимости input ищется заново, а итог
проверяется по видимым tag-chip. После пятого тега исчезновение input считается
нормальным, если все пять ожидаемых chip уже видимы.

## Готовность видео и комментарии

Раннее `Уже можно публиковать` не является разрешением на клик. Нужно дождаться
одновременно:

- `Загрузили и обработали видео`;
- `Готово: можно публиковать и смотреть`;
- активной точной кнопки `Опубликовать` или `Отправить`.

Только после этого MVP выставляет `Кто может комментировать = Все пользователи`,
повторно убеждается, что финальная кнопка активна, и нажимает её ровно один раз.

## Логирование

Ключевой success marker:

```text
КЛИК ПУБЛИКАЦИИ ВЫПОЛНЕН ОДИН РАЗ
```

Лог также содержит `draftId`, стадии правого нижнего статуса, подтверждение пяти
тегов, комментариев и факт закрытия браузера runner-ом.

## Dry-run

`run-dzen-dry-run.cmd` пока сохраняет старый диагностический
`dzen-publish.js --dry-run`. Он не является каноническим live-алгоритмом и не
выполняет финальный клик.

## Операторский запуск

```powershell
cd "C:\TRASH\NotebookLMBot"
.\run-dzen-publish.cmd --date=2026-08-27
```

## Следующий изолированный эксперимент

Следующий локальный MVP должен до открытия формы upload проверить Studio →
`Публикации` → `Видео` по видимой части заголовка до ` | `. Если уже существует
`ИИ-Сводка на <дата>`, новый upload не должен начинаться. Этот duplicate-check
сначала проверяется локально и не считается частью подтверждённого baseline,
пока не пройдёт живой тест.

## Граница эксперимента

Native Dzen upload остаётся отдельным локальным операторским экспериментом и не
является частью nightly GitHub production или обычного NotebookLM worker. RSS
для нативной доставки видео закрыт как неуспешное направление.
