# Нативная загрузка видео в Дзен через локальный Яндекс.Браузер

Этот документ описывает **экспериментальный операторский** browser-upload путь
для уже готового NotebookLM MP4. Он использует тот же защищённый профиль
Яндекс.Браузера и проверенный browser/CDP bootstrap локального `worker.js`.

Путь **не подключён** к обычному `worker.js`, `run-worker.cmd`,
`run-worker-hidden.vbs` или Планировщику Windows. Обычный NotebookLM worker не
публикует видео в Дзен. Реальная публикация выполняется только отдельной явной
операторской командой `run-dzen-publish.cmd`.

## Browser bootstrap

`run-dzen-publish.cmd` и `run-dzen-dry-run.cmd` запускают
`dzen-browser-runner.js`, который использует `browser-session.js` и тот же
профиль/исполняемый файл/CDP lifecycle, что и рабочий `worker.js`.

Оператору не нужно предварительно запускать браузер, PowerShell launcher или CDP.
Bootstrap не удаляет и не пересоздаёт browser profile, cookies, Google session,
Dzen session или session-файлы профиля.

Для **live publish** один явный операторский запуск выполняет ровно один
`dzen-publish-direct.js` child-проход в пределах 10 минут. Если этот проход
завершается ошибкой, runner сохраняет уже известный draft/state и завершает
команду с ошибкой: автоматического перезапуска полного live-flow через 5 секунд
больше нет. Возобновление возможно только следующим отдельным явным операторским
запуском. Диагностический `--dry-run` пока сохраняет старое ограниченное
10-минутное recovery-окно с повтором диагностического child.

После первого single-pass live-теста 27.08.2026 подтверждён отдельный startup-race:
сразу после `domcontentloaded` текст ожидаемого канала может ещё отсутствовать в
DOM, хотя тот же защищённый профиль и канал ранее успешно работали. Поэтому
`dzen-publish-direct.js` теперь не делает одноразовую проверку через короткую
фиксированную паузу, а ждёт до **20 секунд** появления точного
`dzenUpload.channelName`. Это ожидание происходит внутри того же child и той же
страницы, не перезапускает flow и не создаёт upload/draft. Login по-прежнему
является немедленной ошибкой; если ожидаемый канал так и не подтверждён, live-run
останавливается до открытия формы загрузки.

## Подтверждённый ручной сценарий 27.08.2026

На канале «Заметки из подпространства» вручную подтверждён следующий UI-flow:

1. открыть Дзен-студию;
2. `+` → «Загрузить видео»;
3. передать локальный MP4;
4. дождаться `videoEditorPublicationId`;
5. заполнить название, описание, обложку, теги и комментарии;
6. наблюдать правый нижний статус загрузки/обработки;
7. дождаться одновременно:
   - `Загрузили и обработали видео`;
   - `Готово: можно публиковать и смотреть`;
   - активной кнопки `Опубликовать`;
8. нажать `Опубликовать`;
9. подтвердить появление новой записи именно во вкладке **«Видео»**.

Именно этот UI-flow является эталоном автоматизации. Состояние справа внизу, а
не побайтное совпадение внутреннего значения textarea, является авторитетным
сигналом готовности видео к публикации.

## Канонический live-flow

`run-dzen-publish.cmd` через `dzen-browser-runner.js` запускает
`dzen-publish-direct.js`. Live-flow выполняется **в одной странице video draft**:

```text
MP4 upload
  -> videoEditorPublicationId
  -> однократное заполнение metadata
  -> обложка
  -> 5 tag-chip
  -> comments best-effort
  -> больше metadata не переписывать
  -> ждать правый нижний статус «Готово»
  -> baseline одноимённых Видео
  -> один клик «Опубликовать»
  -> verify count increase in Studio -> Видео
```

Главное отличие от ранних экспериментов: live-flow больше не содержит цикла
`fill -> exact compare -> fill` для description. После однократного заполнения
описание проверяется по содержимому без учёта пробельного форматирования. Если
Дзен самостоятельно меняет только пробелы/переносы, это записывается в лог, но
поле **не переписывается снова**. При resume уже совпавшее по непробельному
содержимому описание также не получает `Tab` или иного клавиатурного события.
Непробельное изменение текста остаётся ошибкой.

Это устраняет наблюдавшийся эффект, когда повторные попытки изменения controlled
textarea заставляли поле мигать и могли накапливать пробелы внутри URL.

## Состояния загрузки/обработки

`dzen-publish-direct.js` отслеживает реальный текст формы и логирует смену стадий:

- `Загружаем видео ... не закрывайте Дзен` → upload;
- `Загрузили видео` + `Обрабатываем...` → processing;
- раннее `Уже можно публиковать` не считается финальной готовностью;
- только `Загрузили и обработали видео` +
  `Готово: можно публиковать и смотреть` + активная точная кнопка
  `Опубликовать` разрешают финальный клик.

Таким образом автоматизация ждёт именно состояние, видимое оператору в правом
нижнем углу формы.

## Метаданные

Название строится по дате выпуска:

```text
ИИ-Сводка на 27 августа 2026 | Подпишись, чтоб получать свежее!
```

Описание:

```text
Что происходит в мире Искусственного Интеллекта (ИИ, AI) и Нейросетей на текущий момент - коротенько о самом главном

Без рекламы и воды на 27.08.2026:
- Глобальные новости
- Новости ИИ России
- Выводы и тренды

Этот выпуск:
https://rybalka.one/posts/2026-08-27/
https://dzen.ru/suite/7971db4c-2a4e-449f-b8bf-c3907486d6f1
```

Дата и URL выпуска берутся из выбранного job. Текущие пять тегов:

```text
ии
ai
полезныесоветы
будущее
лайфхак
```

Все пять тегов обязательны и должны стать отдельными tag-chip. При повторном
открытии уже подготовленного draft Дзен может скрыть поле ввода тегов после
заполнения лимита; отсутствие input в этом состоянии не является ошибкой, если
в UI подтверждены все пять ожидаемых tag-chip. Если хотя бы одного chip нет и
input также недоступен, подготовка остаётся блокирующей ошибкой.

Настройка `Кто может комментировать = Все пользователи` остаётся best-effort: её
ошибка логируется через `!!! DZEN:`, но сама по себе не блокирует публикацию.

## Draft recovery

`videoEditorPublicationId` и draft URL сохраняются в `state.json` как можно
раньше. Если сохранённый draft открывает пустую форму `Выбрать видео` или вместо
редактора редиректится в обычную Studio dashboard, он сохраняется в
`previousDrafts` и не переиспользуется. Удалённый draft автоматически не
удаляется.

Нормальный live-run не переоткрывает draft в цикле: upload, metadata, ожидание
готовности и финальный клик выполняются в одном child-проходе. Resume используется
только при **следующей отдельной операторской команде**, если предыдущая команда
реально завершилась с ошибкой до подтверждённого publish click и сохранённый draft
пригоден для безопасного продолжения.

Если существующий draft действительно открывает заполненный video editor,
`dzen-publish-direct.js` продолжает его вместо создания нового. При таком явном
resume сначала ищется уже открытая страница с тем же `videoEditorPublicationId`,
а на распознавание заполненного редактора даётся до 15 секунд.

После выявленного live-дефекта 27.08.2026 введена ревизия direct-flow. Draft без
текущей ревизии не переиспользуется для нового чистого теста: его ссылка только
переносится в `previousDrafts`, а удалённый черновик в Дзене не удаляется.

## Защита от повторного клика

Перед кликом автоматизация открывает Studio → `Публикации` → `Видео` и сохраняет
число уже существующих записей с тем же заголовком. До самого клика состояние
остаётся `READY_TO_PUBLISH`. Сразу после единственного клика сохраняется:

```text
PUBLISH_CLICKED_UNVERIFIED
```

и только после подтверждённого увеличения baseline:

```text
PUBLISHED
```

Если клик уже мог произойти, но проверка не подтвердила результат, сохраняется
`PUBLISH_CLICKED_UNVERIFIED`; повторный запуск **не нажимает кнопку ещё раз**, а
только перепроверяет результат. Старый промежуточный `PUBLISHING` читается
консервативно как legacy ambiguous state и также не разрешает автоматический
повторный клик, но новый direct-flow больше не записывает его до клика.

## Dry-run

`run-dzen-dry-run.cmd` пока сохраняет старый диагностический
`dzen-publish.js --dry-run`. Он не является каноническим live-алгоритмом и не
выполняет финальный клик. Его можно использовать для selector/формы diagnostics.

## Операторский запуск

Реальная публикация:

```powershell
cd "C:\TRASH\NotebookLMBot"
.\run-dzen-publish.cmd --date=2026-08-27
```

Диагностика без финального клика:

```powershell
.\run-dzen-dry-run.cmd --date=2026-08-27
```

Предварительный ручной запуск браузера/CDP не требуется.

## Граница эксперимента

Native Dzen upload остаётся отдельным локальным операторским экспериментом и не
является частью nightly GitHub production или обычного NotebookLM worker. После
подтверждённого живого автоматического прохода отдельно принимается решение о
promotion в обычный worker/Task Scheduler flow.
