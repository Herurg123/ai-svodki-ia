НАСТРОЙКИ NotebookLMBot
=======================

АНТИВИРУС: ОБЯЗАТЕЛЬНО ДО ПЕРВОГО ЗАПУСКА
------------------------------------------
Рабочую папку локального образа NotebookLMBot нужно сразу после её создания
и до копирования, восстановления, npm ci или первого запуска добавить в
исключения активной антивирусной программы.

Для текущего развёртывания:

  C:\TRASH\NotebookLMBot

Если рабочая папка выбрана другая, исключение должно указывать только на
фактический TargetDir.

Это обязательное операторское требование. Worker запускает Node.js, управляет
Яндекс.Браузером через Playwright/CDP, использует PowerShell/DPAPI и
ffmpeg-static. Поведенческие эвристики антивирусов могут помещать отдельные
runtime-файлы в карантин или удалять их, после чего локальный образ становится
частично повреждённым.

Не отключать антивирус целиком и не добавлять в исключения весь диск, весь
профиль пользователя или C:\Program Files. Исключение должно быть узким:
только рабочая папка NotebookLMBot.

Защищённый профиль Яндекс.Браузера находится отдельно и этим исключением
автоматически не охватывается.

Если антивирус уже вмешивался в рабочую папку, сначала добавить её в исключения,
затем восстановить канонические файлы и зависимости и только после этого
выполнять проверочный запуск.

Основные настройки находятся в config.json.
Файл должен оставаться корректным JSON в UTF-8.

ВАЖНО О ФОРМАТЕ
----------------
1. В JSON нельзя писать комментарии через // или /* ... */.
2. true и false пишутся без кавычек.
3. Пути Windows внутри JSON содержат двойные обратные слеши: C:\\Папка\\Файл.
4. После редактирования config.json полезно проверить его командой:

   powershell -NoProfile -Command "Get-Content -Raw 'C:\TRASH\NotebookLMBot\config.json' | ConvertFrom-Json | Out-Null; Write-Host 'config.json OK'"

НАСТРОЙКИ БРАУЗЕРА
------------------

_helpFile
  Имя основного файла справки, указанного в config.json. На работу worker.js
  не влияет.

browserExecutable
  Полный путь к browser.exe Яндекс.Браузера.
  Не заменять на комплектный Chromium Playwright.

browserProfile
  Путь к защищённому профилю автоматизации с Google-сессией,
  NotebookLM, ZeroOmega и прокси. Профиль нельзя очищать или пересоздавать.

browserDebugHost
  Адрес CDP. Для локального запуска должен оставаться 127.0.0.1.

browserDebugPort
  Порт CDP, через который Playwright подключается к Яндекс.Браузеру.
  По умолчанию: 9222. Порт должен быть свободен перед запуском worker.js.

browserStartupTimeoutMs
  Сколько миллисекунд ждать запуска браузера и появления CDP.
  45000 = 45 секунд.

minimizeBrowserWindow
  Управляет видимостью роботизированного окна Яндекс.Браузера.

  true  = запускать и удерживать окно свёрнутым. Это режим по умолчанию.
          Включает повторное сворачивание после открытия рабочей вкладки
          и защиту от разворачивания во время скачивания видео.

  false = оставить окно видимым, чтобы наблюдать работу NotebookLM.
          Playwright по-прежнему работает через CDP и не двигает физический
          курсор. Защита сворачивания при скачивании тоже отключается.

  Для временного просмотра работы заменить:

    "minimizeBrowserWindow": true

  на:

    "minimizeBrowserWindow": false

  После наблюдения вернуть true.

closeBrowserAfterRun
  true  = закрывать роботизированный Яндекс.Браузер после запуска worker.js.
  false = оставлять его открытым. Обычно должно быть true.

clearSessionRestore
  true = перед запуском удалять только файлы восстановления предыдущей
         сессии браузера, чтобы не открывались старые вкладки.
  Это не очищает профиль, cookies или Google-сессию.

КАТАЛОГИ И ФАЙЛЫ
----------------

workDir
  Рабочая папка проекта.

  Эту папку нужно заранее добавить в исключения активного антивируса.
  Для текущего развёртывания:
    C:\TRASH\NotebookLMBot

  Не расширять исключение на весь диск или весь профиль пользователя.

downloadDir
  Каталог для готовых MP4 и постоянного реестра скачиваний.

screenshotsDir
  Каталог диагностических скриншотов при ошибках.

tracesDir
  Каталог трассировок Playwright, если они создаются диагностикой.

tempDir
  Временные файлы worker.js.

regularLog
  Обычный журнал работы worker.log.

errorLog
  Подробный журнал ошибок !!! ERROR !!!.log.

logRotation
  Группа настроек автоматической ротации журналов. Ротация выполняется
  самим worker.js после получения worker.lock, отдельная задача
  Планировщика Windows не требуется.

logRotation.enabled
  true  = включить ротацию журналов.
  false = не архивировать и не удалять журналы автоматически.

  По умолчанию: true.

logRotation.archiveDir
  Каталог архивных журналов.

  По умолчанию:
    C:\\TRASH\\NotebookLMBot\\logs

  Активные журналы продолжают находиться по прежним путям:
    C:\\TRASH\\NotebookLMBot\\worker.log
    C:\\TRASH\\NotebookLMBot\\!!! ERROR !!!.log

  Архивные файлы получают имена:
    worker-YYYY-MM-DD.log
    error-YYYY-MM-DD.log

  Если в течение одного дня срабатывает ротация по размеру, добавляется
  порядковый номер:
    worker-YYYY-MM-DD-2.log

logRotation.workerRetentionDays
  Сколько календарных дней хранить архивы обычного worker.log.

  По умолчанию: 7.

  При значении 7 сохраняются журналы текущего дня и предыдущих шести дней.
  Более старые архивы удаляются при следующем запуске worker.js.

logRotation.errorRetentionDays
  Сколько календарных дней хранить архивы !!! ERROR !!!.log.

  По умолчанию: 30.

  Ошибки хранятся дольше обычного журнала, потому что редкие сбои могут
  понадобиться для последующей диагностики.

logRotation.maxFileSizeMb
  Максимальный размер одного активного журнала в мегабайтах.

  По умолчанию: 25.

  Если worker.log или !!! ERROR !!!.log достигает этого размера до смены
  даты, файл немедленно переносится в архив, а запись продолжается в новом
  активном журнале по прежнему пути.

  Ротация выполняется:
  - при смене календарной даты по timeZone;
  - при превышении maxFileSizeMb;
  - очистка старых архивов выполняется при каждом запуске worker.js.

  Ротация не затрагивает:
  - state.json;
  - постоянный реестр скачанных видео;
  - MP4;
  - диагностические скриншоты;
  - резервные копии worker.js и config.json.

stateFile
  Текущее состояние выпусков и этапов обработки. Кроме NotebookLM/FTP и
  dzenAutomation здесь хранится отдельный job.dzenCollections с независимыми
  status для video и digest.

descriptionFile
  Текстовый файл с описанием последнего выпуска.
  Если для текущего выпуска в блоке «Этот выпуск:» вторая строка уже
  содержит полноценный http/https URL вместо заполнителя «https://»,
  worker считает ссылку добавленной вручную и больше не перезаписывает
  этот файл в рамках текущего выпуска. На следующую дату, когда первая
  ссылка выпуска изменится, файл снова обновится автоматически.

successRegistryFile
  Постоянный реестр успешно скачанных видео. Не удалять и не пересоздавать.

ИСТОЧНИК ВЫПУСКА
----------------

rssUrl
  RSS, в котором worker.js ищет публикацию за текущую дату.

postsBaseUrl
  Базовый адрес публикаций. Ожидаемый URL строится как YYYY-MM-DD/.

timeZone
  Часовой пояс, по которому определяется текущая дата выпуска.
  Для проекта: Europe/Moscow.

NOTEBOOKLM И ПРОВЕРКА IP

  Главная страница NotebookLM.

ipCheckUrl

АВТОМАТИЧЕСКАЯ ПУБЛИКАЦИЯ В ДЗЕН И ПОДБОРКИ
--------------------------------------------

run-worker.cmd
  Запускает full-worker.js, то есть полный трёхфазный цикл по расписанию:
  1) scheduled-worker.js -> worker.js -> NotebookLM/MP4/PNG/FTP;
  2) Dzen duplicate guard -> при необходимости один fresh upload -> один publish
     click -> verification во вкладке «Видео» -> PUBLISHED;
  3) dzen-collections.js -> видео дня в «Видеосводки по ИИ» и ежедневная сводка
     в «Сводки по ИИ».

full-worker.lock
  Внешний lock всего трёхфазного запуска. Следующий 10-минутный trigger не входит
  в новую browser-фазу, пока предыдущий полный запуск ещё работает.
  scheduled-worker.lock остаётся внутренним lock первых двух фаз.

dzenUpload.automaticEnabled
  true  = после локального job.status=DONE автоматически выполнить Dzen-фазу.
          Это production default. Если параметр отсутствует в старом config.json,
          он также трактуется как true.
  false = оставить NotebookLM/FTP по расписанию, но не запускать Dzen автоматически.
          Подборки также не запускаются, потому что ждут PUBLISHED.
          Ручные Dzen-команды при этом остаются доступны.

dzenUpload.verificationTimeoutMs
  Сколько времени после publish child ждать появления ожидаемого заголовка во
  вкладке Studio -> Публикации -> Видео. По умолчанию 90000 мс.

Dzen safety state хранится внутри текущего job в state.json:
  PENDING / RETRYABLE_PRE_CLICK = после duplicate guard допустим fresh upload;
  PUBLISH_ARMED                 = live child уже вооружён, новый upload запрещён;
  CLICKED_UNVERIFIED            = child завершился после клика, только verification;
  BLOCKED_AMBIGUOUS             = исход клика не доказан, только verification;
  PUBLISHED                     = публикация подтверждена во вкладке «Видео».

Из PUBLISH_ARMED, CLICKED_UNVERIFIED и BLOCKED_AMBIGUOUS автоматический worker
никогда не делает второй publish click. Повтор fresh upload допускается только
после явного child-лога publishClicked=false.

Dzen collections state:
  job.dzenCollections.video.status  = PENDING или ADDED;
  job.dzenCollections.digest.status = PENDING или ADDED;
  aggregate status = PENDING / PARTIAL / COMPLETE.

  video  -> «Видеосводки по ИИ»
            https://dzen.ru/suite/a899d818-52b3-4f87-8e49-4a4bac375244
  digest -> «Сводки по ИИ»
            https://dzen.ru/suite/7971db4c-2a4e-449f-b8bf-c3907486d6f1

  При COMPLETE браузер для подборок больше не открывается. При PARTIAL следующий
  запуск обрабатывает только PENDING цель. Отсутствующая same-day публикация
  остаётся PENDING и может появиться к следующему запуску.

  Live-проверенный already-added marker Дзен: точное название подборки имеет
  computed color rgba(6, 6, 15, 0.6). Alpha <= 0.70 означает already-added и
  запрещает повторный click.

ПРИМЕР ВРЕМЕННОГО НАБЛЮДЕНИЯ
----------------------------

1. Убедиться, что full-worker/worker сейчас не запущен.
2. Поставить в config.json:

   "minimizeBrowserWindow": false

3. Запустить worker вручную:

   cd /d C:\TRASH\NotebookLMBot
   run-worker.cmd

   Команда node worker.js используется только для NotebookLM-only диагностики.
   Команда node scheduled-worker.js используется только для диагностики первых
   двух фаз и не запускает подборки.

4. После проверки вернуть:

   "minimizeBrowserWindow": true

Ручная диагностика подборок:

  run-dzen-collections-debug.cmd --date=YYYY-MM-DD
  run-dzen-collections-apply.cmd --date=YYYY-MM-DD

Первая команда не кликает по плашке, вторая применяет тот же production-код.

FTP-ДОСТАВКА ВИДЕО
------------------

ftpUpload
  Группа настроек доставки уже скачанного видео на FTP.
  FTP-этап выполняется только после успешного локального скачивания MP4.

ftpUpload.enabled
  false = FTP-доставка отключена. Это безопасное значение по умолчанию.
  true  = после скачивания создать локальное PNG-превью и отправить
          видео с превью на FTP.

ftpUpload.accessFile
  Путь к отдельному локальному JSON-файлу с параметрами FTP-доступа.
  Этот файл не следует копировать в общие архивы или публиковать.

ftpUpload.remoteDir
  Защитное ограничение удалённого каталога. В этой версии worker.js
  допустимо только точное значение:

    "video"

  После подключения worker проверяет каталог video и создаёт его,
  если каталога ещё нет. В другие каталоги worker не переходит.

ftpUpload.remoteFilenamePrefix
  Латинский префикс удалённых файлов. По умолчанию:

    ai-svodka

  Например, для выпуска 2026-08-25 на FTP появятся:
    video/ai-svodka-2026-08-25.mp4
    video/ai-svodka-2026-08-25.png

  Локальные имена при этом не меняются:
    ИИ-Сводка 2026-08-25.mp4
    ИИ-Сводка 2026-08-25.png

ftpUpload.publicBaseUrl
  Необязательный публичный HTTPS-адрес каталога video.
  Если заполнен, worker запишет итоговые URL видео и превью в state.json
  и постоянный реестр скачиваний. Сам FTP-upload от этого параметра
  не зависит.

  Пример, если каталог FTP video публикуется именно по этому адресу:
    https://rybalka.one/video/

ftpUpload.previewEnabled
  true = создать PNG из первого декодируемого кадра MP4 и положить его
         рядом с локальным видео, затем загрузить оба файла.
  false = загрузить только видео.

  Для создания PNG используется пакет ffmpeg-static. Отдельно ставить
  FFmpeg в Windows не требуется.

ftpUpload.connectTimeoutMs
  Тайм-аут FTP-команд в миллисекундах. По умолчанию: 30000.

Файл FTP-доступа
  По умолчанию:
    C:\TRASH\NotebookLMBot\ftp-access.json

  Заполните файл данными отдельной FTP-учётки до включения
  ftpUpload.enabled.

Ограничения FTP-безопасности
  - worker создаёт только каталог video, если его нет;
  - worker загружает только текущие MP4 и PNG в этот каталог;
  - существующий удалённый файл правильного размера считается уже
    загруженным и не меняется;
  - существующий удалённый файл другого размера не удаляется и не
    перезаписывается: worker завершит FTP-этап ошибкой;
  - временный upload-файл создаётся только внутри video и после ошибки
    worker пытается удалить только этот собственный временный файл;
  - другие файлы и каталоги FTP не удаляются, не переименовываются и
    не перезаписываются.

Повтор после FTP-ошибки
  Успешное локальное скачивание остаётся статусом DONE.
  Если FTP временно недоступен, следующий запуск не открывает NotebookLM
  и не скачивает видео повторно. Он повторяет только создание превью,
  если оно ещё отсутствует, и FTP-доставку существующего локального файла.

Установка зависимостей FTP/превью
  Для штатной установки зависимостей используется committed package-lock.json.
  Выполнить:

    C:\TRASH\NotebookLMBot\install-ftp-support.cmd

  Этот helper выполняет npm ci --no-audit --no-fund и не переписывает
  package.json или package-lock.json.

  После установки полезно проверить:

    node --check worker.js
    node --check full-worker.js
    node --check scheduled-worker.js
    node --check dzen-collections.js
    npm test
