DZEN COLLECTIONS: РУЧНАЯ ДИАГНОСТИКА И PRODUCTION-КОНТРАКТ
==========================================================

Этот файл сохраняет прежнее имя от отладочного этапа 29.08.2026, чтобы при
обновлении C:\TRASH\NotebookLMBot старые файлы заменялись поверх и каталог не
обрастал версиями. Каноническая реализация теперь находится в
`dzen-collections.js` и автоматически запускается третьей фазой полного worker.

Штатный путь:

  Task Scheduler
  -> run-worker.cmd
  -> full-worker.js
  -> scheduled-worker.js
  -> NotebookLM / MP4 / PNG / FTP / Dzen publish
  -> dzen-collections.js

Этап подборок запускается только после подтверждённого
job.dzenAutomation.status=PUBLISHED.

Для даты выпуска обрабатываются максимум две публикации:

1. Видео
   `ИИ-Сводка на <дата> | Подпишись, чтоб получать свежее!`
   -> `Видеосводки по ИИ`
   -> https://dzen.ru/suite/a899d818-52b3-4f87-8e49-4a4bac375244

2. Ежедневная сводка
   `ИИ-Сводка на <дата>`
   -> `Сводки по ИИ`
   -> https://dzen.ru/suite/7971db4c-2a4e-449f-b8bf-c3907486d6f1

Состояние хранится отдельно для video и digest в `job.dzenCollections`.
Подтверждённая цель получает status=ADDED. Когда обе цели ADDED,
status=COMPLETE, и следующие scheduled runs не открывают браузер для этапа
подборок. Если подтверждена только одна цель, следующий запуск обрабатывает
только вторую.

Live-проверка 29.08.2026 установила, что уже добавленная плашка подборки остаётся
формально hit-testable, но точный title визуально приглушён до
`rgba(6, 6, 15, 0.6)`. Поэтому alpha <= 0.70 является подтверждённым
already-added signal и второй клик запрещён.

Ручная диагностика без изменения подборок:

  run-dzen-collections-debug.cmd --date=YYYY-MM-DD

Ручное применение:

  run-dzen-collections-apply.cmd --date=YYYY-MM-DD

При ошибке этап пишет в worker/error log, при возможности делает screenshot и
закрывает роботизированный Яндекс.Браузер. Автоматического второго клика после
неоднозначного результата нет.
