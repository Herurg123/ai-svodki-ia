# Финансовая контрольная точка до Sol, 24 октября 2026

## Данные владельца до начала контрольного Sol shadow

**Источник:** скриншот панели OpenAI Usage, переданный владельцем в чате
24 октября 2026 года **до ручного запуска** `sol-24-paid-once`.
Скриншот не добавлен в Git; этот файл фиксирует отображённые цифры
и границы их интерпретации. Результаты Sol за 24 октября в этой
контрольной точке не измерялись.

| Показатель на скриншоте | Значение |
|---|---|
| Project filter | `AI Svodki` |
| API sources | `All API sources` |
| API keys | `All API keys` |
| Период графика | `Last 7 days`, group by `1d` |
| Дневная точка `Oct 24, 2026 UTC` (all) | **$0.38** |
| October spend / Personal | **$10.68 / $10.00** |
| Total tokens за отображаемый период | **11,807,546** |
| Total requests за отображаемый период | **206** |

Владелец подтвердил, что **$0.38 — уровень расходов на момент до
контрольного Sol эксперимента** и относит этот уровень к
штатному выпуску Terra. Технически суточная точка охватывает
**все источники и ключи выбранного проекта**, поэтому сама по себе
не является помодельным invoice для Terra.

### Методика последующей сверки

1. Выполнить не более **12 новых Sol Responses** в одном однократном
   GitHub Actions run, сохраняя каждый `response_id`, `usage`,
   `service_tier`, число searches и две расчётные оценки стоимости
   (Standard/tier-adjusted).
2. После завершения получить от владельца новый скриншот Usage
   **с тем же project filter и датой Oct 24 UTC**, либо выгрузку
   биллинга по запросам/проекту.
3. Сопоставить `new Oct 24 UTC total - $0.38`. Разность будет
   **приблизительной оценкой приращения**, а не доказанной платой за
   Sol, пока не исключены другие вызовы и задержки обновления панели.
4. Сохранить оба значения раздельно: observed billing delta и
   per-request usage-based estimate. Не подменять одно другим.
5. Проверить распределение затрат по UTC, особенно если часть
   эксперимента/другие API вызовы перейдут на следующую дату.
6. Превышение October spend `$10.68/$10.00` выглядит как
   превышение показанного месячного бюджета; **не трактовать
   автоматически как жёсткую блокировку API** без отдельного
   подтверждения настроек биллинга.
