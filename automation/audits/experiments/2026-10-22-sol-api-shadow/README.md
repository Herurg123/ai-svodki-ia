Восьмой результат неизвестен и не восстанавливается из догадок.

Фактическую стоимость отдельного Sol run по скриншоту нельзя изолировать, поскольку это все проекты/модели за день и данные могут задерживаться.

## Стоимость: не подгонять коэффициент к графику

В проектном `usage_ledger.py` приняты стандартные **публичные list prices** Terra
`$2/M input, $0.20/M cached, $2.50/M 30m write, $12/M output, $0.01/search`.
Полученные `$4.2361` за 22 октября являются модельной суммой по полному ledger,
**не счётом**. У Sol первые 7 ответов дают ещё одну list-price оценку
`$0.7898865`, а восьмой ответ остался без usage.
Обе суммы нельзя автоматически приравнивать к деньгам, отражённым в кабинете.
Возможно различие тарифного режима, учёта, времени обновления или охвата;
ни одна причина пока не установлена. Умножитель «×0.1» не обоснован.

## Безопасность и дальнейшее действие

- **Платных вызовов при офлайн-правке и CI нет.** API script запускается только с
  `--paid` и отдельно выданной переменной
  `SOL_SHADOW_OWNER_APPROVAL_USD=1.00`. Новое разрешение пока отсутствует.
- Максимум: 1 USD на **новую серию** при отдельном согласии, conservative usage-guard,
  25 настоящих Web Searches и no automatic SDK retry.
- Это клиентская оценка, не жёсткий server-side лимит расходов.
- Никогда не повторять уже сохранённые семь вызовов; на следующем прогоне
  требовать исходный ZIP `SOL_SHADOW_REPLAY_ARTIFACT`.
- Текущий branch содержит экспериментальные файлы, но не меняет production.
- Полный Research/Editorial по одному дню не является достаточной базой для замены Terra.
