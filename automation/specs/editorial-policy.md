# Редакционная спецификация проекта «ИИ-сводки»

Версия: 2026-08-05
Статус: утверждённая каноническая спецификация
Язык публикации: русский

Этот документ является источником истины для research-промпта, editorial-промпта, Python-валидаторов, сборщика сайта, RSS и архива. Содержательные требования нельзя удалять, сокращать или заменять без отдельного согласования.

## 1. Архитектура

Рабочая цепочка:

1. GitHub-архив и `stories.json` задают контекст антидублей.
2. Research-этап собирает и проверяет кандидатов.
3. Editorial-этап выбирает сюжеты и создаёт статью.
4. Код нормализует технические метаданные.
5. Image API получает полный `image_prompt`.
6. Сборщик создаёт HTML, общий индекс и RSS.
7. Валидаторы проверяют выпуск.
8. Только после успешной проверки допускаются commit и FTP-деплой.

Blogger, Google Sheets и ручное копирование не являются частью production-архитектуры.

## 2. Временное окно

Основное окно поиска:

`search_cutoff_at` предыдущего выпуска → фактический pre-research cutoff
текущего запуска.

Cutoff фиксируется до первого Web Search. В архиве он берётся из сохранённого
`research.search_window.end_at`; для старых artifacts — из `run-info.started_at`;
`published_at` используется только как fallback. Нормализованные 06:00 МСК
остаются временем публикации, но не границей, способной потерять событие между
фактическим стартом research и 06:00. Если между выпусками были пропущены
календарные дни, окно всё равно начинается с последнего успешного cutoff.

Если источник показывает точное время, кандидат хранит:

- `published_at`;
- `published_date`;
- `time_precision: "datetime"`.

Если источник показывает только дату:

- `published_at: null`;
- `published_date`;
- `time_precision: "date"`.

Материал с точностью только до даты допускается по календарной дате и получает внутреннюю заметку о неполной точности времени.

Дата сегодняшней перепечатки не обновляет старое событие. Кандидат обязан
различать `freshness_status: "new_event"`, `"material_update"` и
`"old_reprint"`; последний всегда исключается, если нет отдельного нового
факта внутри окна.

## 3. Антидубли и обновления

Проверять архив за 7–14 дней.

Не повторять тему без существенного нового факта.

Сравнивать:

- смысл события;
- компанию или игрока;
- дату события;
- источники;
- URL;
- заголовки;
- записи `stories.json`;
- текущий `archive/index.json`.

Если тема уже была, но появился важный новый факт:

- `archive_status` должен быть `update`;
- заголовок сюжета обязан начинаться с `Обновление:`;
- новый факт должен быть явно описан;
- основной URL должен вести на материал об обновлении.

Для новой новости префикс `Обновление:` запрещён.

## 4. Количество сюжетов

Общая цель выпуска:

- 7–12 сюжетов.

Это обычный объём, а не минимальное условие публикации.

Для китайских и российских новостей числовых квот нет. Research обязан
проверять оба направления, но отсутствие или малое число достойных
региональных новостей не останавливает выпуск и не требует добивать его
слабыми либо старыми материалами.

Если достойные китайские или российские сюжеты найдены, редактор включает
столько значимых сюжетов, сколько действительно есть. Если таких сюжетов нет,
соответствующий раздел и его заголовок полностью отсутствуют.

Если найдено 1–6 достойных сюжетов:

- выпуск публикуется;
- `status` остаётся `ok`;
- `short_digest` устанавливается в `true`;
- первый элемент `article_html` должен быть:

```html
<p><em>Новостей сегодня меньше, чем обычно</em></p>
```

- эта пометка является первым блоком `article_html`; сборщик ставит обложку
  перед `article_html`, поэтому на странице и в RSS пометка находится сразу
  под изображением;
- в `editorial_notes` добавляется запись `low_news_volume`.

Ограниченный coverage audit может попытаться дополнить короткий выпуск до
обычного объёма. Отсутствие новых кандидатов или региональный пробел не
блокируют публикацию, если все шесть обязательных поисков завершены.
Дополнительные навигационные tool items также не являются ошибкой бюджета.
Технически неполный audit блокирует публикацию уже готового выпуска с 1–6
достойными сюжетами до успешного recovery недостающих направлений.

Если не найдено ни одного достаточно подтверждённого сюжета:

- `status: "error"`;
- публикация не создаётся.

Нельзя включать формулировки вида «по компании новостей нет».

## 5. Разнообразие

Мягкие цели:

- не более двух выбранных сюжетов от одного издателя;
- не более двух выбранных сюжетов по одной компании или организации.

Превышение разрешено, если:

- события независимы;
- каждое событие имеет высокую значимость;
- причина сохранена в `selection.diversity_overrides`.

Без объяснения превышение считается ошибкой валидации.

Reddit и социальные сети допустимы только как сигнал для проверки по
независимому надёжному источнику.

### 6.6. Legal / copyright / scraping

Legal/copyright/scraping проверяется отдельно от общего регулирования. В
кандидаты попадают только события масштаба `major`: решение значимого суда или
регулятора, дело с крупным участником или группой правообладателей, существенной
суммой, прецедентом либо потенциальным влиянием на обучение моделей,
лицензирование, использование данных, распространение продукта или отрасль.

Сам факт подачи иска недостаточен. Мелкий локальный или бытовой спор имеет
`legal_scale: "minor"` и не может получить `include` или `consider`. Для
принятого legal-кандидата обязательны `category: "legal"`,
`legal_scale: "major"`, `significance_score >= 4`, надёжный судебный,
регуляторный или новостной источник и текстовое объяснение масштаба.

### 6.7. Курьёз или необычный факт

Отдельный проход может найти один реальный, проверяемый и самостоятельно
значимый необычный, парадоксальный или забавный ИИ-сюжет. Его отсутствие
нормально. Сатира, розыгрыш, художественный текст, слух и обычный анонс с
придуманным забавным заголовком не подходят.

В выпуске разрешён максимум один выбранный кандидат категории `curiosity`.
Он обязан иметь `verification_status: "verified"`,
`curiosity_eligible: true`, `significance_score >= 3` и явное объяснение
проверки. Курьёз не вытесняет более важную серьёзную новость.

### 6.8. Ограниченный coverage audit

Coverage audit запускается только для пула короче обычной цели и выполняет
шесть обязательных однотематических Web Search-проходов:

1. `security_world`;
2. `security_russia`;
3. `security_asia`;
4. `legal_copyright_scraping`;
5. `curiosity`;
6. `general_coverage_gaps` — авторитетный last-mile sweep, сохраняющий все
   прежние направления research и отдельно проверяющий первоисточники,
   агентства, суды и регуляторов через доменный фильтр API. Reuters входит в
   список, но не является единственным источником.

Каждый проход выполняется отдельным запросом с `max_tool_calls=1`. Общий
предел — 7 завершённых Web Search операций с `action.type=search`; седьмой
вызов разрешён только как повтор первой незавершённой обязательной проверки.
Служебные `web_search_call` с `action.type=open_page` или `find_in_page`
сохраняются в траектории, но не расходуют search-бюджет и не останавливают
остальные направления. Повышать предел выше 7 без отдельного
согласования запрещено. Основной research отдельно ограничен 12 Web Search
calls, поэтому суммарный дневной потолок равен 19.

Повторный editorial из-за audit выполняется только когда после проверки
временного окна, дублей, источников и содержательных порогов действительно
добавлен хотя бы один пригодный кандидат. Завершение research-only recovery
учитывается отдельно и не называется повтором из-за audit.

Диагностика сохраняет обязательные, проверенные, частичные и непроверенные
направления; фактические поисковые запросы и источники из API response; число
всех tool items, навигационных действий и завершённых `search`; исход
направления (`candidates_found`, `no_news_found`, техническая ошибка);
кандидатов и причины отклонения по направлению; исчерпание бюджета;
число добавленных кандидатов и факт editorial rerun. Содержательный статус:

- `complete` — все шесть направлений проверены;
- `complete_with_gaps` — все проверены, но в части направлений достойных
  событий нет;
- `partial` — выполнена только часть обязательных проверок, бюджет ещё не
  исчерпан;
- `budget_exhausted` — лимит закончился до завершения всех направлений;
- `error` — ни одна обязательная проверка не дала пригодной диагностики.

`complete_with_gaps` отличается от технической неполноты: он означает, что
все шесть поисков состоялись, но часть не нашла достойной новости. Только
`complete` и `complete_with_gaps` разрешают короткий выпуск. Статусы `partial`,
`budget_exhausted` и `error` обязаны быть видны в artifact и Actions Summary и
останавливают Image API, commit и deploy. При recovery завершённые направления
не повторяются; выполняются только недостающие проверки в остатке общего
бюджета.

Приоритет источников:

1. официальные блоги и документация;
2. пресс-релизы;
3. научные публикации;
4. регуляторные, судебные и государственные документы;
5. GitHub;
6. Hugging Face;
7. arXiv;
8. крупные деловые и технологические медиа;
9. Reuters, AP, Bloomberg и сопоставимые агентства.

Не пересказывать рекламные и телеграмные формулировки как факт.

Если утверждение подтверждено только лендингом, пресс-релизом или соцсетями, называть его продуктовым анонсом или заявлением компании, а не независимой оценкой.

Отделять факты от слухов, заявлений сторон и прогнозов.

Не включать шум, пустые инфоповоды и материалы без существенного факта.

## 8. Структура `article_html`

`article_html` не содержит:

- `<h1>`;
- `<img>`;
- `<html>`;
- `<head>`;
- `<body>`;
- `<script>`;
- `<style>`;
- `<iframe>`;
- Markdown;
- служебный текст.

`<h1>` и обложку добавляет сборщик.

Обычный выпуск начинается со вступления из 2–4 предложений.

Короткий выпуск начинается с точной фразы:

```html
<p><em>Новостей сегодня меньше, чем обычно</em></p>
```

После неё идёт обычное вступление.

Разделы:

```html
<h2>Мировые лидеры ИИ</h2>
<h2>Китайские лидеры ИИ</h2>
<h2>Российские лидеры ИИ</h2>
<h2>Что это значит</h2>
<h2>Все ИИ-Сводки</h2>
```

Разделы с китайскими и российскими новостями выводятся только при наличии соответствующих выбранных сюжетов. Пустые разделы запрещены.

## 9. Структура каждой новости

Каждый сюжет содержит:

```html
<h3>Заголовок новости</h3>
<p>Первый содержательный абзац.</p>
<p>Второй содержательный абзац.</p>
```

Допускается третий абзац.

Итого: 2–3 содержательных абзаца на сюжет.

Объяснять:

- что произошло;
- что подтверждено;
- почему это важно;
- ограничения и неопределённости;
- применимые последствия для рынка;
- продуктов;
- исследований;
- бизнеса;
- автоматизации;
- маркетинга;
- разработки;
- создателей ИИ-контента.

Не требуется искусственно затрагивать все направления в каждой новости.

Источники ставятся только HTML-ссылками:

```html
<a href="URL">Название источника</a>
```

Markdown-ссылки запрещены.

## 10. Раздел «Что это значит»

Обязательная структура:

```html
<h2>Что это значит</h2>
<ol>
  <li>...</li>
</ol>
```

Количество выводов: 4–6.

Выводы должны вытекать из выбранных сюжетов, а не быть общими лозунгами.

## 11. Блок Дзена

В конце статьи обязателен точный блок:

```html
<h2>Все ИИ-Сводки</h2>
<p><a href="https://dzen.ru/suite/7971db4c-2a4e-449f-b8bf-c3907486d6f1">Архив ИИ-Сводок</a></p>
```

Заголовок `<h2>Все ИИ-Сводки</h2>` не изменять.

Текст ссылки должен быть `Архив ИИ-Сводок`.

## 12. Маркировка Meta

Правило применяется только к видимому тексту `article_html`.

Если статья упоминает Meta:

1. первое видимое упоминание должно быть `Meta*`;
2. все последующие видимые упоминания должны быть `Meta`;
3. в `stories.json`, `sources.json`, `topics`, URL, атрибутах HTML и служебных полях писать `Meta` без звёздочки;
4. после блока Дзена добавить ровно одну сноску:

```html
<p><em>*Meta и ее сервисы - в России запрещены</em></p>
```

Если Meta в статье отсутствует, сноска запрещена.

Нельзя ставить звёздочку у каждого упоминания.

## 13. Терминология и стиль

Писать:

- `ИИ`, а не `AI`;
- `агент ИИ`, а не `AI agent`;
- `LLM` без перевода;
- названия компаний и продуктов не переводить.

`AI` допускается внутри официального названия компании или продукта, например `Mistral AI`.

Стиль:

- ясно;
- делово;
- живо;
- без воды;
- без чрезмерного хайпа.

## 14. Технические метаданные

Код, а не модель, задаёт:

- `date`;
- `slug`;
- `title`;
- `published_at`;
- `author`;
- `cover_filename`.

Источник значений:

- `publication_date`;
- `site.json`;
- `editorial.json`;
- шаблон имени файла;
- часовой пояс;
- час публикации.

## 15. `editorial_notes`

`meta.json` содержит:

```json
{
  "editorial_notes": []
}
```

Допустимые типы заметок:

- `source_gap`;
- `low_news_volume`;
- `time_precision`;
- `diversity_override`;
- другие технические редакционные ограничения.

Эти заметки:

- сохраняются в GitHub;
- видны в artifact и Job Summary;
- не публикуются автоматически в статье;
- не попадают в RSS.

## 16. `stories.json`

Видимый CSV не публикуется.

Для каждого выпуска сохраняется `stories.json`.

Минимальная карточка сюжета:

```json
{
  "candidate_id": "cand-001",
  "section": "world",
  "headline": "Заголовок новости",
  "organization": "Meta",
  "topic": "генерация изображений",
  "event_type": "отключение функции",
  "status": "new",
  "summary": "Краткое описание",
  "published_at": "2026-07-11T10:30:00Z",
  "published_date": "2026-07-11",
  "time_precision": "datetime",
  "sources": [],
  "keywords": [],
  "geography": "world",
  "category": "multimodal"
}
```

`stories.json` используется для:

- антидублей;
- определения обновлений;
- анализа тем;
- контроля компаний;
- анализа издателей;
- построения `archive/index.json`;
- будущей статистики.

## 17. Промпт изображения

`image_prompt` должен быть на русском языке и содержать четыре смысловых блока:

1. тип изображения и точный заголовок;
2. главные визуальные темы;
3. композиция;
4. стиль и запреты.

Точный заголовок:

`ИИ-Сводка на D месяца YYYY`.

Постоянные ограничения:

- формат 16:9;
- без логотипов компаний;
- без дополнительного текста, кроме точного заголовка;
- без водяных знаков;
- без мелких интерфейсных надписей;
- без пустой половины кадра;
- без стокового корпоративного клипарта;
- без узнаваемых лиц реальных людей;
- нейтральные силуэты без идентифицируемых черт допустимы.

Полный `image_prompt` передаётся в Image API напрямую, без художественного переписывания и без программного наложения заголовка как основного режима.

## 18. Ошибки

`status: "error"` используется, если:

- не найдено ни одного достойного сюжета;
- невозможно подтвердить ключевые факты;
- нарушена строгая JSON-схема;
- ссылки не проходят проверку;
- итоговый HTML не проходит обязательную валидацию;
- сборка или RSS невалидны;
- изменён рабочий `posts/` во время preview.

Малое количество новостей само по себе ошибкой не является.

## 19. Что намеренно не возвращается из старой задачи

Не используются:

- Blogger как production-архив;
- Google Sheets;
- ручной HTML code block;
- текстовая строка `СТАТУС` внутри статьи;
- видимый CSV;
- некликабельный URL Дзена;
- ручное копирование;
- отдельная задача «ИИ-сводка — Лаборатория промпта».

Эквиваленты:

- `СТАТУС` → `digest.status` и `run-info.json`;
- CSV → `stories.json`;
- Blogger → GitHub content и `archive/index.json`;
- HTML для копирования → автоматически собранная страница.
