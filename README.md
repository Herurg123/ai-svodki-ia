# ИИ-Сводки

Репозиторий производственного конвейера ежедневных аналитических выпусков об искусственном интеллекте.

Публичные адреса:

- Дзен: https://dzen.ru/rybv
- сайт выпусков: https://rybalka.one/posts/
- RSS для Дзена: https://rybalka.one/posts/rss.xml
- sitemap: https://rybalka.one/posts/sitemap.xml

## Производственный цикл

- `.github/workflows/ci.yml` проверяет pull requests, направленные в `main`, и изменения самого `main` без платных API-вызовов;
- `.github/workflows/daily-production.yml` выполняет исследование, редакционную сборку, генерацию обложки и обновление `posts/`;
- `.github/workflows/repository-cleanup.yml` ежедневно в 01:43 по Москве компактирует рабочие материалы и полностью удаляет публичные выпуски старше 32 дней, одновременно пересобирая RSS, индексы и sitemap;
- `.github/workflows/deploy-posts.yml` синхронизирует точное состояние `posts/` через изолированного FTP-пользователя, включая удаление исчезнувших страниц и обложек.

## Правила очистки контента и мусора

Единый ночной workflow применяет одну и ту же границу хранения к GitHub,
публичному сайту и связанным файлам:

- удаляются только выпуски, дата которых **строго раньше** даты
  `сегодня − 32 дня`; сама граничная дата и всё более новое сохраняются;
- старые `automation/content/YYYY-MM-DD/` компактируются: удаляются статья,
  обложка, промпты, сырые ответы API и другие производственные файлы, но
  `meta.json` и `stories.json` остаются для редакционной дедупликации;
- из `posts/` удаляются просроченные страницы и связанные изображения,
  включая исторический пакет `dzen-test`;
- после удаления из того же набора актуальных выпусков пересобираются
  `posts/rss.xml`, `posts/dzen-test/rss.xml`, оба `index.html` и
  `posts/sitemap.xml`, поэтому в них не остаётся ссылок старше 32 дней;
- после успешной проверки согласованное состояние записывается одним commit
  в `main`, а FTP синхронизируется именно с этим SHA и удаляет файлы,
  которых больше нет в `posts/`;
- перед публикацией commit проверяется соответствие RSS, дат, страниц,
  изображений, индексов и sitemap. Любое расхождение, попытка затронуть
  свежий выпуск или удалить последний элемент основного RSS останавливает
  workflow, не изменяя `main`;
- запуск по расписанию применяет очистку автоматически. Ручной запуск по
  умолчанию работает как dry-run, а срок хранения нельзя уменьшить ниже
  32 дней;
- подробная GitHub Actions Summary по-русски показывает найденные и удалённые
  файлы, освобождённый объём, сохранённые JSON, новый размер RSS и commit;
  итоговая Summary отдельно показывает результат FTP-синхронизации.

## Основные каталоги

- `automation/content/YYYY-MM-DD/` — структурированный контент выпусков; у выпусков старше 32 дней остаются только `meta.json` и `stories.json` для поиска дублей;
- `automation/archive/index.json` — агрегированный архив редакционной дедупликации;
- `automation/config/` — производственная конфигурация;
- `automation/scripts/` — генераторы и валидаторы;
- `automation/tests/` — регрессионные тесты;
- `posts/` — публикуемый статический сайт, RSS, sitemap и обложки; публичное окно хранения составляет 32 полных календарных дня.

Технические детали находятся в `automation/README.md`.
